# Stacki selective upstream audit

Reviewed on 2026-09-16 from Stellar kickoff `eac9459` in isolated branch `codex/stacki-selective-upstream`. The first batch adapts a testing method and fixes two demonstrated defects in Stellar's original source engine. No upstream source, runtime dependency, serializer, write queue or history implementation is copied.

## Observed source and reproducibility

A fresh temporary clone of [Stacki](https://github.com/flowtricks/stacki) resolved its default branch to [fd2a38f](https://github.com/flowtricks/stacki/commit/fd2a38f), release 0.1.26. This matches the kickoff observation. Compare the preserved [800fa52](https://github.com/flowtricks/stacki/commit/800fa52) baseline with that exact head, rather than a moving branch. Exact revisions and separate reviewed/ported fields are in [provenance](../provenance/sources.json).

The range has 60 commits and 397 changed files, with 22,633 insertions and 7,698 deletions. Subject categories are 31 refactors, five builds, nine docs, one style, one merge, three features, five fixes and five tests. Those counts describe labels, not proof that a refactor preserves behavior: the queue cap is embedded in a refactor. The checked [commit inventory](../evidence/stacki-upstream/upstream-commits.tsv) and [file inventory](../evidence/stacki-upstream/upstream-files.tsv) reproduce the range with `git log --reverse --format='%H%x09%s' 800fa52..fd2a38f` and `git diff --name-status 800fa52 fd2a38f` in the temporary reference. The reference is not a Stellar build dependency and no preserved adjacent checkout was modified.

Most churn converts Electron/renderer modules to TypeScript and introduces shared IPC contracts, build gates, declarations and ratchets. Final release `fd2a38f` repairs a renderer startup failure caused by serving the new CommonJS contracts to native Vite imports. Importing the migration wholesale would introduce unrelated architecture and its repair sequence into Stellar's independent Next/runner design.

## First-batch implementation and evidence

The implementation remains within [editor-core](../../packages/editor-core/src/index.ts). `TextDecoder` now retains the BOM. A single CSS parser helper records the length difference between original text and PostCSS's normalized input; all declaration and insertion coordinates include that prefix before UTF-8 byte calculation. Standard property keys fold only ASCII uppercase letters; `--` custom properties keep their spelling and case-sensitive identity. Independent review also reproduced escaped CSS identifiers hiding duplicate standard or custom properties. The engine conservatively refuses owned rules with escaped declaration names and makes token edits read-only when any escaped property prevents proving token uniqueness across the allowed stylesheets. This does not implement general CSS escape normalization. It refuses unsupported syntax and ambiguous source rather than normalizing whole files.

[Preservation tests](../../packages/editor-core/src/preservation.test.ts) failed before the change: mixed-case duplicate ownership was editable; BOM edits refused; mixed-case replacements inserted a second property; a BOM-only source change returned the wrong stale-model outcome. The corrected corpus produced 27 failing tests/subtests before and all 42 editor tests/subtests passing after the review follow-up. Logs: [before](../evidence/stacki-upstream/regressions-before.log), [after](../evidence/stacki-upstream/regressions-after.log). There are 128 generated edit cases inside 32 deterministic subtests, not 128 independent randomized trials.

[Browser acceptance](../../test/editor-e2e/upstream-preservation.mjs) uses temporary project copies, separate credentials and dynamically allocated app/runner/preview ports. It exercises a BOM/CRLF stylesheet with Unicode text and a mixed-case property, UI review/apply, computed preview color, exact-byte undo/redo, duplicate-owner refusal, an independent edited Astro build, clean production output and unchanged seed/other project. Its result and verification logs are recorded in the [evidence directory](../evidence/stacki-upstream/). Existing user services and saved data are outside this harness.

## Deferred watcher convergence

`WorkspaceRuntime.startWatcher` schedules `serial(refreshSource)` every 400ms. `serial` appends to a promise chain. When one snapshot takes longer than the interval, reads accumulate and later user operations wait behind the backlog. The auditor's bounded executable probe replaced only `refreshSource` with a 650ms in-memory delay, started/stopped the timer and drained its own mutex; it opened no files or services. The [probe](../evidence/stacki-upstream/watcher-backlog.mjs) reproduces this against built runner code. This is a known deferred issue, not a queue fix shipped by this batch. Coordinate runner ownership, coalesce pending/in-flight watcher reads and prove apply/close ordering in a separate slice.
