# Architecture Trail

This directory documents how Stellar subsystems work today. Keep one file per substantial subsystem, not one per session. Record the purpose, key concepts, behavior, extension points, known gaps, and last review date. Ground claims in current code and link to source files. Diagrams are welcome when they make relationships or flows easier to understand; keep them alongside the relevant explanation.

The operations log records chronology, the current-work file records the next action, and PRDs record intended behavior. Update an architecture note when shipped subsystem behavior changes. The optional `./../../.claude/commands/doc-it.md` prompt points to this shared documentation practice; it does not perform automatic work.
