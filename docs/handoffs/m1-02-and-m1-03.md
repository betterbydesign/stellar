# M1-02 runner and M1-03 source-engine handoff

Local implementation is on `codex/m1-02-project-runner`, based on `703e12c` plus the preserved, uncommitted M1-01 changes. Three SOL high agents supplied isolated runner, broker and engine work; the coordinator integrated and independently reviewed it. No commit, push, remote CI run, PR or deployment is part of this handoff.

## Implemented surface

- `apps/runner`: two fixed working copies, one owner per data directory, actual Astro worker readiness, process/session lifecycle, source revisions, strict paths, proposal storage, guarded one-file writes and crash-recoverable receipts.
- `apps/web`: server-only loopback broker; `/api/operator/bootstrap`, `/api/operator/session`, project/session APIs and the `/connect` operator page. Every project read is authenticated; mutations also require exact Origin and CSRF. The app hostname is `127.0.0.1`; preview hostname is `localhost`.
- `packages/editor-core`: pure Astro/CSS analysis, revision-scoped targets, minimal base/mobile local style and base-token proposals, reset and guarded inverse helpers. There is no filesystem/process behavior in its implementation and no copied Stacki source.
- Root commands and CI: package builds, real runner tests, standalone fixture build and `verify:local` production app-to-runner acceptance. `dev:local` launches the connected development adapter. Next's automatic nested agent-instruction generation is disabled so the root harness remains canonical.

The starter home page remains a bootstrap shell. Project selection, canvas instrumentation, inspector and user-facing undo/redo are still M1-04 through M1-06. Local execution accepts reviewed fixture code and is not a hosted or hostile-code sandbox.

## Contracts for the next agent

Use `packages/contracts` rather than parallel request shapes. A session's source revision is persistent; its ID and preview generation are replaceable. Restart can return a new session ID. Bind future frame capabilities to the returned session, generation, exact origin and current revision.

The API prefix is `/api/projects/{projectId}/sessions/{sessionId}`. Source-model reads take `pageId` and a new logical-operation `requestId`. Prepare/apply take the shared typed body. Request lookup is `/changes/requests/{lookupRequestId}?requestId={newLookupRequestId}`; a new authorized session can inspect the original receipt but cannot reuse an old session's proposal authority. Separate prepare, apply and lookup IDs; reuse an ID only when retrying the same operation and intent.

`createSourceModel({snapshot, manifest, projectId, sessionId, requestId, projectRevision, pageId})` returns the typed model. `prepareSourceChange({snapshot, manifest, model, request})` returns ready/unchanged/refused. Element `targetId` is the revision-scoped source key. `resolveSourceSelection(model, {sourceKey, anchor, occurrenceId})` validates source identity; runtime occurrence/frame trust is the bridge's responsibility. Repeated component internals remain read-only.

`applySourcePatch(bytes, patch)` and `createInversePatch(patch, appliedBytes)` operate on bytes only. Inverse preparation requires that reversing the supplied postimage reproduces the original full-file digest. The runner must still authorize and revalidate any inverse before a future undo. Do not implement a separate history store: operation records already retain preimages, postimages, authorized proposals, ordered application sequence and receipts. History controls are deliberately disabled today. No retention pruning runs in M1-02.

M1-04 can supply the trusted `apps/runner/src/preview-integration/index.mjs` integration through the in-memory Astro configuration seam. Keep browser instrumentation development-only and preserve normal project config/source. The runner's Vite file-serving allowlist includes only the working copy, pinned dependencies and that trusted integration directory when supplied.

## Review findings resolved

The coordinator required parser ownership/alias checks, full-postimage inverse guards, malformed request-ID handling and proof that an inserted declaration remains distinct. Runner review fixed occupied-port false readiness, cancelled startup, process cleanup, source coverage, semantic manifest drift, pending-intent recovery before new work, old-session queued writes, chronological history and competing runner ownership. Recovery arbitration rechecks the owner under an exclusive guard; an ambiguous interrupted guard fails closed. Main-process shutdown drains broker requests before releasing the data lease.

A real production test found that NextURL normalizes `127.0.0.1` to `localhost` inside `Request.url`. Authorization now accepts that framework representation only at the same protocol/port while still requiring the exact incoming `Host` and browser `Origin`. Regression tests reject an actual alternate Host/Origin. Broker restart validation likewise permits a new coherent session only for successful restart responses.

## Practical limits

Supported concurrent writes go through one local runner. Atomic replacement detects observed conflicts but cannot exclude an arbitrary external editor in the final check/rename window. Preserve working copies and journals on rollback. The fixed fixture manifest may be reformatted; changing its semantics is refused. Source snapshots are bounded, and unknown/ambiguous CSS ownership is intentionally read-only. The pinned dependency install is shared by trusted copies; this is not dependency or OS isolation.

Proceed with [M1-04 canvas and selection](../prds/m1-04-canvas-and-selection.md). M1-05 consumes the same edit API for controls, and M1-06 adds guarded history mutations and the final save/reload/reopen visual proof.
